## Rewrote @agentix/testing for the v2 core per SPEC section 4.

### apiNotes
Exports (packages/testing/src/index.ts barrel): association, contract, deterministic, ensures, harness, http, recording, test-application, trace. Key surfaces for downstream phases: (1) createTestApplication({features, adapters?, overrides?, mode? (default "test"), authorize?}) -> {app, calls, clock, ids}. Coverage is per-port: ports covered by user adapters are never faked and never recorded (core forbids two adapters per port, so individual ops of covered ports cannot be overridden either — overrides for them throw). overrides are keyed by port-operation id "portId.opKey" (e.g. "noteStorage.get"); unknown keys throw a TypeError listing all valid keys. calls is {all(), of(effectId), reset()} with RecordedEffectCall entries (recorded inputs are the schema-parsed effect inputs). Underivable ops get a throwing stub; through dispatch this surfaces as fault EFFECT_FAILURE whose error.cause message names the override key. Store detection is structural (opKey get/save/delete/list with kinds read/write/write/read), because PortOperationDescriptor carries no marker linking back to port.store — semantics exactly mirror Port.memory() (save keyed by value.id). Clock: ISO strings starting 2000-01-01T00:00:00.000Z, +1000ms per now(); falls back to epoch millis when the op's output schema rejects strings but accepts numbers. Ids: "id-1", "id-2", ... (2) testHttp(handler) types the handler STRUCTURALLY as {fetch(request: Request): Promise<Response>} — no adapters-http import; client methods get/delete(path, opts?) and post/put/patch(path, body?, opts?) plus request({method, path, body?, headers?, principal?, token?}); token becomes "authorization: Bearer <token>" unless authorization is already set; principal is JSON.stringify'd into the exported TEST_PRINCIPAL_HEADER = "x-agentix-test-principal" — the adapters-http package (or app tests) should read that header in a test authenticate hook to round-trip principals. Response is {status, body (JSON-parsed; undefined when empty or unparseable), headers (Headers), text (raw)}. (3) Harness: testCommand/testQuery take {application, operation, input, principal?, trace? (default true)}; application is the structural HarnessApplication (just the descriptor dispatch overload), so any Application<Ops> works without variance games; operations are the bound descriptors (feature.operations.<key>). (4) createRecordingAdapter(port, plainValueHandlers) returns an object that IS a BoundPortAdapter structurally (descriptorType/portId/operations) plus calls()/reset() — pass it straight into createApplication adapters (bindPort no longer exists). (5) ensures.ts replaces the deleted invariant module: checkEnsures(operation, {input, output}) -> violated names, assertEnsures throws EnsureViolationError, checkEnsuresProperty runs a seeded fast-check property (fast-check dependency retained and used).

### coreChangeRequests
- Optional (not blocking): PortOperationDescriptor has no marker identifying it as part of a port.store preset, and port descriptors are not reachable from operation effects, so createTestApplication detects store ports heuristically (opKey get/save/delete/list + matching read/write kind). A tiny non-generic tag on store-bound ops (e.g. readonly preset?: "store") would make the .memory()-equivalent fake selection exact instead of heuristic. Current behavior is equivalent to .memory() for matching ops, so this is a robustness nicety only.

### openIssues
- testHttp's principal option depends on the exported TEST_PRINCIPAL_HEADER ("x-agentix-test-principal") convention: the parallel adapters-http rewrite (or app-level tests) must wire an authenticate hook that reads this header for principal round-trips; token uses the standard Authorization Bearer header and needs no coordination.
- createTestApplication fakes at per-port granularity: a user adapter that covers a port but misses a reachable op fails app startup with core INCOMPLETE_ADAPTER (not patched by the test harness), because core forbids a second adapter for the same port.
- calls records only auto-bound/overridden fakes; user-supplied adapters are not recorded — wrap them with createRecordingAdapter if a log is needed (documented in the source).
- packages/testing/README.md still documents the v1 API; the spec assigns README/API.md rewrites to the docs sweep phase (SPEC section 7), so it was left untouched.
- Unrelated concurrent edits to packages/compiler/src/{files.ts,types.ts} exist in the shared worktree from the parallel compiler agent — not part of this change.

## Full v2 rewrite of packages/adapters-http per SPEC section 2

### apiNotes
Package exports unchanged: "." (root = web surface + Node host), "./web" (edge-safe, zero node: imports), "./node". EXPORTED SURFACE (root & ./web unless noted):

createHttpHandler<Ops>(app: Application<Ops>, options?: CreateHttpHandlerOptions): HttpHandler.
- CreateHttpHandlerOptions = { authenticate?: PrincipalExtractor; onError?: HttpErrorObserver; routes?: readonly HttpRouteOverride[] }.
- HttpHandler = { fetch(request: Request): Promise<Response>; handle(request: HandlerRequest): Promise<HandlerResponse>; routes: CompiledRouteTable }. handle() is the runtime-neutral engine both entries and serveNode use — P4 benchmarks can call it directly with plain strings (no undici anywhere).
- Routes AUTO-derived from every registered operation carrying http metadata. Overrides (options.routes) must reference the app's registered descriptor identity (TypeError otherwise) and REPLACE all auto routes of the operations they reference; duplicate method+path-shape throws TypeError at creation (e.g. /x/:a vs /x/:b).

Request flow (BOTH entries): route match -> authenticate -> authorize -> body -> parse -> map -> dispatch -> envelope.
- authenticate absent => anonymous. Extractor returning null => ANONYMOUS (not 401); ops without permissions still succeed anonymously (core A2). Throwing AuthenticationError => 401 {ok:false,error:{code:<error.code, default "UNAUTHENTICATED">}}. Any other extractor throw => 500 + onError.
- Core exported authorize(operation, principal) gates 403 BEFORE readBody; body is never touched on 403 (custom mapRequest also runs after the central body read, so overrides cannot break this). Pre-body 403 body is opaque: {ok:false,error:{code:"PERMISSION_DENIED"}} (missingPermissions deliberately NOT exposed); dispatch-level PERMISSION_DENIED (custom app authorize hook) returns the same opaque 403.
- Envelope: completed ok => status = override.status ?? http.status ?? 200, body {"ok":true,"value":...}; completed error => status = route.errorStatus[code] ?? 422 (errorStatus derived from unified error {http} declarations, override.errorStatus merged over it), body {"ok":false,"error":{code,details}}; INVALID_INPUT => 400 {"ok":false,"error":{"code":"INVALID_INPUT","issues":[...]}}; malformed JSON => 400 {"code":"INVALID_JSON"}; unknown route => 404 {"code":"NOT_FOUND"}; wrong method => 405 {"code":"METHOD_NOT_ALLOWED"} + Allow header (sorted, ", "-joined); body over cap => 413 {"code":"PAYLOAD_TOO_LARGE"}; fault => 500 {"code":"INTERNAL"} (opaque) + onError(faultError, {method,path,operationId}). content-type always "application/json; charset=utf-8".
- onError?: (error, info: HttpErrorInfo{method,path,operationId?}) => void; default console.error ONLY when app.mode === "development", no-op in production AND test.
- Default mapRequest: if operation.input is an object schema, merge precedence body < query < path-params, keyed by input .shape: ALL plain-object JSON body keys copied (strict schema still rejects unknown keys), query/params contribute only shape keys; string values coerced per schema description (number, boolean, numeric/boolean literals; optional/refinement unwrapped; unions NOT coerced); non-coercible strings pass through for the schema to reject with issues. Non-object input schema => parsed body passed as input verbatim. Empty/absent body => {} base.

defineHttpRoute<Operation>(options: DefineHttpRouteOptions<Operation>): HttpRouteOverride<Operation> — the ONLY escape hatch. { method: HttpMethod | lowercase, path, operation, status?, errorStatus?: Record<code,number>, mapRequest?(context: HttpRequestContext) => Awaitable<Infer<Operation["input"]>> }. HttpRequestContext = { method, path, params, query (first-value-wins record), body (already-parsed JSON), headers(name) }. Validates path/method/status ranges eagerly. mapResponse is GONE — the envelope is fixed.

Routing (router.ts): compileRouteTable(operations: Iterable<AnyBoundOperation>, overrides?): CompiledRouteTable { routes: readonly CompiledRoute[]; buckets: ReadonlyMap<method, RouteBucket{staticRoutes: ReadonlyMap<path,CompiledRoute>; paramRoutes: readonly CompiledRoute[]}> }. CompiledRoute = { method, path (normalized), operation, operationId, successStatus, errorStatus, segments: RouteSegment[], paramCount, staticSegmentCount, buildInput(params,queryString,body), mapRequest? }. matchRoute(table, method, rawPath): {kind:"matched",route,params} | {kind:"method_not_allowed",allow} | {kind:"not_found"}. Precedence: raw static Map hit -> decoded-segment second-chance static lookup (only when path contains "%") -> param routes sorted staticSegmentCount desc, paramCount asc, path lex. Param segments percent-decoded; malformed encoding skips that candidate only. Trailing slash normalized. 405 Allow computed lazily over other buckets. Method matching expects uppercase (Node/undici guarantee).

auth.ts: HttpRequestView { method, path, headers(name)=>string|undefined } (case-insensitive lookup); PrincipalExtractor = (view) => Awaitable<Principal|null>; AuthenticationError(message?, code?); createBearerPrincipalExtractor({resolve(token, view)}); createTrustedHeaderPrincipalExtractor({idHeader?="x-principal-id", permissionsHeader?="x-principal-permissions", separator?=","}). No undici Request anywhere.

serveNode(handler, {port (0 = ephemeral), host? = "127.0.0.1", maxBodyBytes? = 1_048_576}): Promise<NodeHttpServer{server, url, close(): Promise<void>}> — ROOT and "./node" export only (edge "./web" excludes it). Raw req/res via handler.handle: single URL-string split, header closure over req.headers, single-copy body decode (1-chunk fast path), content-length fast 413 reject, constant envelopes pre-encoded to Buffers, writeHead with precomputed content-length, res.end(Buffer). close() also closes idle keep-alive sockets. createNodeHttpListener is DELETED.

Other exports: HandlerRequest (extends HttpRequestView + {query: string (raw, no "?"), readBody(): Promise<string|undefined>}), HandlerResponse {status, body: string, headers?}, RequestBodyLimitError (throw from custom hosts' readBody for 413), JSON_CONTENT_TYPE, EMPTY_PARAMS, queryRecord(query), types Awaitable/BuildInput/MatchResult/RouteBucket/RouteSegment/HttpErrorInfo/HttpErrorObserver, re-export type HttpMethod from core. handler.ts additionally exports INTERNAL_ERROR_BODY and RESPONSE_BODY_CONSTANTS (consumed by node.ts; intentionally NOT in the web barrel).

### coreChangeRequests


### openIssues
- 401 semantics changed vs v1: an extractor returning null now yields an ANONYMOUS request (authorize decides 403) instead of 401; 401 only via AuthenticationError. P3 apps/acceptance porting should rely on 403 for missing credentials on permissioned ops.
- Both pre-body and dispatch-level PERMISSION_DENIED responses are opaque {code:"PERMISSION_DENIED"} (no missingPermissions/principalId leak). If the shared-contract acceptance asserts the richer v1 403 body, it needs the opaque form.
- A custom createApplication authorize hook is invisible to the adapter (core Application does not expose it); the pre-body gate uses the exported default authorize(). Stricter custom-hook denials still return 403, but only after the body was read (via the dispatch rejection).
- handler.fetch enforces no body cap (edge runtimes cap upstream); maxBodyBytes is a serveNode option only — document in the P4/P7 docs sweep.
- serveNode 413 fast-rejects on declared content-length without draining the request stream; Node then closes the connection after the response (same class of behavior as v1, small race with very large streamed uploads is theoretically possible but not observed in tests).
- Default mapRequest does not coerce union-typed fields (e.g. s.union([s.number(), s.string()])) — values from params/query stay strings; use a defineHttpRoute mapRequest override if needed.
- packages/adapters-http/README.md + CHANGELOG.md still describe the v1 API — deferred to the docs phase per plan (P4/P7 README/API.md deliverable).
