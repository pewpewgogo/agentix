# Core v2 as-built API notes (P1 implementer)

Downstream phases MUST treat packages/core/src as the authority; these notes flag deviations from SPEC/verified-d1.

## Summary
Rewrote packages/core/src to the v2 API per SPEC section 1. schema.ts: s.string({min,max,trim,pattern}), s.number({min,max,int}), ObjectSchema with typed .shape, strict objects, allocation fixes (failure-only lazy path prefixing instead of [...path,key] spreads, creation-time key sort, no freezing of parse products — schemas are mode-agnostic and the runtime freezes in dev/test). descriptors.ts: command/query -> UnboundOperation with injected typed fail(), unified errors {http?,details?} with bare-schema shorthand and derived http.errorStatus on variance-neutral HttpMetadata, feature(id,{operations,events?}) with BindOperations template-literal ids, port(id,{...}) with ops addressable as Port.opName (collision-checked), port.read/write/time/random/external, port.store(id,objectSchema) CRUD preset with .memory() adapter, Port.adapter() returning non-generic BoundPortAdapter (A1 plain-value impls), event(id,version,payload) positional, ensures invariants; all define* factories/aliases deleted. application.ts: createApplication({features,adapters,mode?(NODE_ENV default),authorize?}) with startup validation (duplicate ids incl. derived, adapter coverage via portId/opKey, query purity, HTTP_ROUTE_CONFLICT), exported authorize(operation,principal) single permission gate (anonymous OK when no permissions, Set reused when provided), precomputed per-operation fast path (effect handler closures bound once, compiled emit/ensure/error tables, id->op Map), dispatch keeping 3-way completed/rejected/fault semantics with trace machinery fully absent unless trace:true, fault latching + drainPendingEffects surviving trace-off, production skipping ONLY effect-output re-parse, freezes only in dev/test, event snapshot always + deep-freeze dev/test, ensures post-completion in dev/test with INVARIANT_VIOLATION, and app.call(id,input,opts?) returning Outcome and throwing DispatchError on rejected/fault. index.ts barrel exports s (export * as s) with s.Infer plus top-level Infer. Old tests git-mv'd to packages/core/test/_v1/ and excluded from vitest+tsc; new packages/core/test/v2-smoke.test.ts covers feature+port.store+command+query+fail+call+dispatch+http-metadata+production/test differences (17 tests). Gates: tsc -b packages/core clean, tsc type-tests clean, smoke suite green; verified-d1 generic patterns additionally re-proven against the real implementation (incl. all @ts-expect-error negatives) with an ephemeral probe compiled under the same strict config.

## Deviations / decisions
Deviations from the verified-d1 file, all spec-driven or additive: (1) descriptorType is "operation" for both unbound and bound operations (verified file used "unbound-operation"; a single literal keeps the extends relationship and lets the scanner key on one name; bound ops are distinguished by the presence of id). (2) Per A7 unification, http.errorStatus is NOT authored — AuthoredHttp is {method,path,status?} only, and descriptor HttpMetadata.errorStatus (variance-neutral Readonly<Record<string,number>>) is derived from per-error {http} numbers, so the verified file's keyof-Errors AuthoredHttp check became moot. (3) Port ops lost their error channel per spec (input/output only), so PortOperationDescriptor drops the Errors param and carries non-generic runtime fields portId/opKey (needed for adapter coverage because BoundPortAdapter is non-generic). (4) execute returns plain output values or fail(...); fail results are branded with the exported FAIL_RESULT symbol so outputs that structurally resemble outcomes cannot be misread; ok()/err() returned from execute would be treated as plain output and fail output validation (the type system forbids it). (5) fail(code) with an error declared without details defaults details to {} validated against a strict empty-object schema; DeclaredError details type for such codes is Record<string,never>. (6) ensures check receives {input,output}, runs only on ok outcomes in dev/test; the optional evidence schema is validated as authoring metadata but not executed at runtime (spec leaves evidence semantics unspecified) — descriptor stores it for tooling. (7) Fault-code set updated for the v2 model: EFFECT_FAILURE and INVARIANT_VIOLATION added; UNDECLARED_EFFECT, INVALID_EFFECT_RESULT, INVALID_EFFECT_ERROR, INVALID_OPERATION_OUTCOME removed as unreachable (effect contexts are precompiled from declared effects only; adapters/execute no longer return Outcomes). Effect INPUT parse is kept in ALL modes; production skips only the effect-output re-parse, exactly per the spec bullet. (8) FeatureDescriptor is {id, operations, events} — deps/contracts/standalone invariants/ports list deleted per spec; adapter coverage is derived from effect descriptors. (9) mode default: NODE_ENV "production"/"test" map directly, anything else (including unset, or non-Node runtimes via globalThis probe) -> "development". (10) The v1 `schema` named export and app-level trace default are dropped (trace is opt-in per dispatch; spec: no trace machinery unless trace:true); factories are exported only under s, with Infer available top-level and as s.Infer. (11) Principal keeps required id+permissions (used for PERMISSION_DENIED principalId) but principal itself is optional everywhere (A2); principal() helper retained. (12) dispatch has two typed overloads (by id and by BoundOperation descriptor) — descriptor dispatch of a foreign same-id descriptor still faults with OPERATION_DESCRIPTOR_MISMATCH. (13) Root vitest.config.ts gained one exclude entry (packages/**/test/_v1/**) so the parked v1 suites are skipped; packages/core/tsconfig.type-tests.json include narrowed to ["src/**/*.ts","test/*.ts"].

## Open issues for later phases

- design-notes/v2-amended sandbox tests use app.dispatch(id, input) returning a bare Outcome; the final API per A9 is app.call(id, input) — the P3 sandbox arm must be adapted to call() (dispatch keeps the 3-way result).
- Old v1 core tests are parked in packages/core/test/_v1/ (git mv) and excluded from vitest/tsc; the next phase rewrites them against the v2 API (application.test.ts:251-252 freeze-contract change is deliberate per spec).
- Event payloads are structurally detached (snapshot) in production without freezing; if the P4 perf loop shows this walk mattering on event-heavy workloads it could be gated further, though the spec measured event-path cost as immaterial (~0.16us).
- authorize custom hook denials report missingPermissions computed by the default subset diff, which is [] when the hook denies despite permissions being satisfied — acceptable but worth documenting in the P7 docs sweep.

Post-P1 fixes applied by the orchestrator: errorDetails/errorStatus records are null-prototype; CallOptions no longer has trace (dispatch is the only trace surface).

## Orchestrator amendment (final adversarial review, 2026-07-26)

- Effect-output re-parse is NO LONGER production-skipped — this overrides SPEC section 1's "production skips ONLY effect-output re-parse" bullet. All modes now safeParse effect outputs, hand execute the detached parsed.data graph, and fault INVALID_EFFECT_OUTPUT on invalid adapter values. Reason (finding #11): the skip silently changed DATA semantics, not just validation — in production execute received the adapter's LIVE object, so a local mutation of a loaded record wrote through to store state and was invisible to every test (tests run mode "test"). Uniform data semantics beats the ~0.16us saving. The remaining production skips are unchanged: ensures postconditions and dev/test deep-freezing.
- Event payload snapshot is identity-gated in production (finding #14): when the payload schema's parse product is already detached (parsed.data !== payload — every built-in schema), production emits the parse product directly instead of running the snapshotStructuredValue copy-walk a second time. Pass-through custom schemas (parsed.data === payload) are still snapshotted in every mode; dev/test still snapshots AND deep-freezes.
- The EFFECTIVE authorization gate is exposed as app.authorize(operation, principal?) (finding #12): the custom createApplication({authorize}) hook when provided, else the exported default subset check. adapters-http's pre-body 403 now calls app.authorize instead of the imported default, so a permissive hook (e.g. admin bypass) works over HTTP and a restrictive hook still denies before the body is read.
- A throwing authorize hook is contained (finding #20): dispatch resolves with a new AUTHORIZE_FAILED fault (never a rejected promise); over HTTP it answers 500 + onError.
- Schema issue accumulation is bounded (finding #13): all push(...spread) sites became capped loops; a parse accumulates at most 100 issues plus one final { code: "too_many_issues" } marker, so huge invalid payloads stay 400-class INVALID_INPUT rejections (previously ~125k nested issues threw RangeError -> INPUT_VALIDATION_FAILED fault -> HTTP 500) and issue lists cannot amplify responses unboundedly. Union parsing caps causes but still tries every option.
- FAIL_RESULT is the REGISTERED Symbol.for("agentix.fail") (finding #15) so declared failures stay recognizable across duplicate module copies of @agentix/core in one process.
- Reserved (prototype-polluting) identifiers "__proto__", "prototype", "constructor" are rejected for feature/port ids, error codes, operation keys (feature and port), and effect aliases (finding #22) — such keys were previously swallowed silently by object assignment.
